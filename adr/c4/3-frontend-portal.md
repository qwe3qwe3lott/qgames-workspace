# C4 · Уровень 3 — маршруты и страницы

Компоненты — [3-frontend](3-frontend.md). Решения: [frontend-apps](../frontend/frontend-apps.md), [room-ui](../frontend/room-ui.md), [player-accounts](../security/player-accounts.md).

## Портал

| URL | Страница | Доступ |
|---|---|---|
| `/` | главная | все |
| `/profile` | логин, ник и аватар, способы входа (пароль, Google) | после входа |
| `/games` | список игр из `GET /api/games` | все |
| `/rooms` | публичные комнаты всех игр (пока не реализован) | все |
| `/games/<код>/rooms` | карточка игры и создание комнаты (список комнат не реализован) | после входа |
| `/games/<код>/rooms/<uuid>` | комната: участники, роли, партия | после входа |

- `<код>` — код игры из контракта (`nothing`, `checkers`, `carcassonne`), один во всём стеке: в URL, в путях API, в `gameCode` настроек simple и advanced, в имени пакета игры. Неизвестный код — 404.
- **Реестр игр** `entities/game/model/registry.ts`: коды и `load` (динамический `import()`). Название, описание и правила игры приходят с бэкенда. Игра без пакета на фронте (сейчас `carcassonne`) — запись без `load`: доска не рисуется, создание комнаты заблокировано.
- **Статус публикации** живёт только на бэкенде. Скрытая игра по прямой ссылке ведёт себя как опубликованная. `GAME_NOT_FOUND` даёт 404 на карточке и «Игра недоступна» в комнате.
- **Авторизованная зона** — pathless layout `routes/_authenticated.tsx`. Его `beforeLoad` загружает пользователя, а гостю показывает `pages/authRequired` с открытым окном входа **на том же адресе**. Отдельной страницы входа нет. После входа маршрут перезагружается (`router.invalidate`).
- **Вход и регистрация — окно `AuthDialog`** (`features/auth`): логин+пароль или Google. На `REGISTRATION_REQUIRED` окно переходит к регистрации, ID token держится в состоянии окна. Регистрация идёт только через Google: неизменяемый логин, необязательный пароль с повтором. Ошибки: `LOGIN_TAKEN` подсвечивает поле, `ACCOUNT_ALREADY_EXISTS` предлагает войти, `INVALID_GOOGLE_TOKEN` просит выбрать аккаунт заново.
- **Google Identity Services:** скрипт загружается по требованию, кнопку рисует GIS. Без `PUBLIC_GOOGLE_CLIENT_ID` кнопки Google скрыты, регистрация недоступна.
- **Настройки комнаты** ([room-settings](../game/room-settings.md)): комната создаётся кнопкой без формы, с настройками по умолчанию. Владелец меняет настройки в модальном окне: места наблюдателей — всегда, правила — между партиями. Галочка «Продвинутые правила» переключает simple/advanced; при включении advanced-поля заполняет `POST /api/games/{код}/advanced-settings`. Границы, пресеты и значения по умолчанию берутся из `rules` ответа `GET /api/games/{код}`, на фронте не хардкодятся.

## Страница комнаты

- **Присутствие = открытый SSE-поток комнаты.** Кнопок «Войти» и «Выйти» нет. Поток открывается при открытии страницы и закрывается при уходе (`features/roomMembership/model/useRoomPresence.ts`). При возврате из bfcache поток переоткрывается. Несколько вкладок допустимы.
- Ушедший игрок идущей партии помечается «отошёл» (`leaving`). Пока поток переподключается, видна плашка «Нет связи с комнатой — переподключаемся…».
- **Роль** меняется кнопкой «Перейти» в заголовке списка «Игроки» или «Наблюдатели». Недоступный переход — заблокированная кнопка с подсказкой о причине.
- **Передача владения:** у владельца в строке каждого присутствующего участника кнопка «Передать владение» с подтверждением. Передача доступна и во время партии.
- **Партия:** доска подписывается на поток партии, когда у комнаты есть `session.id` (в том числе завершённой). «Пауза/Продолжить» показываются только при активном таймере, «Отменить» у владельца есть всегда. После 204 на ход, паузу или продолжение кнопки остаются в pending, пока seq не вырастет (`useSessionAdvance`, таймаут 5 с).

## Админка

| URL | Страница | Доступ |
|---|---|---|
| `/login` | вход по логину и паролю (`?redirect=`) | все |
| `/` | редирект на `/admins` | — |
| `/admins` | список администраторов, у текущего метка «вы» | после входа |

Гость определяется по 401 или 404 `ADMIN_NOT_FOUND` на `GET /api/admin/admins/me` и уходит на `/login?redirect=<адрес>`. `redirect` принимается только как путь этого сайта.
