# Миграции схемы БД

Область: backend · Диаграммы: [erd/*](../erd/game.md) · Код: `backend/<m>/<m>/src/main/resources/db/changelog/<модуль>/`, `backend/app/.../db.changelog-master.yaml`

## Контекст

У каждого модуля свои таблицы, а БД одна. Миграции должны быть переносимыми, легко ревьюиться и выполняться в предсказуемом порядке.

## Решение

- Liquibase, YAML, **только абстрактные изменения** (`createTable`, `createIndex`, `insert`…), без `sql`/`sqlFile`.
- Changelog'и лежат в модуле, в папке с его именем (`DDL/`, `DML/`). Модуль ведёт master со явным списком include, сводный master приложения включает master-файлы модулей.
- Имя файла и `id` changeSet'а — `<yyyy-MM-dd>-<ДЕЙСТВИЕ>-<таблица>`. **Одна таблица — одна миграция**, индексы и ограничения входят в её CREATE. Автор — `git config user.name`.
- Имя таблицы уникально в приложении, префиксов модулей нет. Индексы и ограничения называются по таблице (`room_member_pk`).
- **Существующие миграции не редактируются** (прод запущен): изменения идут только новыми миграциями (`ALTER`, `DROP`, DML).
- ERD в `adr/erd/` обновляется вместе с миграцией и показывает итоговую схему.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Время или порядковый номер в имени миграции | Порядок и так задаёт master |
| Папка на каждую миграцию | Выбрана раскладка `DDL/` и `DML/` |
| SQL-миграции (`sqlFile`) | Диалектный SQL непереносим между БД |
| Префикс модуля в имени таблицы и файла (`"game#room"`) | В одной БД без схем хватает уникальности имён; `#` давал предупреждения Liquibase во вложенных jar |
| `includeAll` | DML, зависящий от DDL, может выполниться не вовремя |
| Фиксированный автор `qgames` | В `DATABASECHANGELOG` не видно, кто автор |
| Несколько таблиц в одной миграции | Сложнее откатывать и ревьюить |
| Правка исходной CREATE-миграции с пересозданием БД | Так было до прода; на проде Liquibase отвергнет изменённый changeSet по контрольной сумме, а данные нельзя пересоздать |

## Последствия

- Нет CHECK и частичных индексов: их нет среди абстрактных изменений Liquibase open source.
- Схема таблицы собирается из нескольких миграций: ERD — единственное место, где она видна целиком.
