# Где живут правила игр

Область: backend · Диаграммы: [c4/3-backend-games](../c4/3-backend-games.md) · Код: `backend/games/*`, чек-лист — `backend/games/CLAUDE.md`

## Контекст

Игр будет много (шашки, Каркассон…), инфраструктура у всех пошаговых игр одинаковая, а правила разные. Правила нужно тестировать без Spring и БД, держать границы между играми и уметь вынести игру в отдельный процесс.

## Решение

- Правила каждой игры — отдельный Gradle-модуль `games/<игра>` на **чистом Kotlin**: без Spring, БД, сети и IO, зависит только от `games/game-core`.
- `game-core` — модель игры (`GameRules`, `SessionEngine`, применитель патчей) и общие блоки состояния (игроки, очерёдность, часы, итог).
- Модуль приложения `game` подключает все `games/*` и отвечает за всё остальное: комнаты, хранение, таймеры, события.
- Новой игре не нужны новый модуль приложения и DDL-миграции.
- «Игра в ничто» — тестовая игра для проверки движка: ходы `PASS` по очереди, число раундов 1–50 из настроек.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Логика игр в `libs/` | `libs/` — только инфраструктура без бизнес-логики |
| Логика игр пакетами внутри модуля game | Границы между играми никто не контролирует, игру нельзя вынести в отдельный сервис |
| «Игра в ничто» без ходов | Не проверяет очерёдность, журнал ходов и конец партии |

## Последствия

- Правила тестируются чистыми тестами в своих модулях.
- Если игре понадобится отдельный процесс (real-time, WebSocket), заводится отдельное приложение с тем же модулем `games/`. Это решение только по согласованию.
