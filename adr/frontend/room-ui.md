# Интерфейс комнаты

Область: frontend · Диаграммы: [c4/3-frontend-portal](../c4/3-frontend-portal.md) · Код: `features/roomMembership`, `pages/room`, `widgets/roomPanel`, `@qgames/ui` (`WithHint`)

## Контекст

На странице комнаты много действий, доступных не всегда (смена роли, пауза, передача владения), а связь может рваться. Пользователь должен понимать, почему действие недоступно, и не делать лишних кликов.

## Решение

- Вход и выход автоматические: присутствие = открытый поток ([room-presence](../game/room-presence.md)). При обрыве видна плашка «Нет связи… переподключаемся», без кнопки.
- Роль меняется кнопкой «Перейти» в заголовке списка, где пользователя нет. Оба списка («Игроки», «Наблюдатели») видны всегда, в заголовке — занято/мест: «Наблюдатели (10/8)» после понижения лимита.
- Комната создаётся кнопкой без формы. Настройки — у владельца в модальном окне, всегда доступном: места наблюдателей меняются и в партии, правила заблокированы с пояснением. Режим simple/advanced переключают сегменты «Простые | Продвинутые» ([room-settings](../game/room-settings.md)).
- Новичку без мест — окончательный отказ «В комнате нет свободных мест», войти можно перезагрузкой страницы.
- Заблокированные действия показывают причину через **Tooltip** (`WithHint` из `@qgames/ui`, общий для портала и пакетов игр).
- В списке участников владелец отмечен короной на аватаре, сам пользователь — обводкой аватара; текстовых меток «Владелец» и «Вы» нет.
- При продвинутых правилах описание комнаты показывает всем «Выбраны продвинутые правила» и «Подробнее…» — модалку со списком текущих правил; при простых — строки игры и времени.
- Кнопки паузы показываются **только при активном таймере**. «Отменить» у владельца есть всегда.
- Ошибки действий вне форм показываются снекбаром.
- **Раскладка по игре.** Доски с фиксированным полем (шашки) — в компактной колонке. Растущее поле (тайлы, «Круассан») объявляет в реестре `layout: 'wide'`: во время партии страница без ограничения ширины, сайдбар комнаты остаётся слева, доска занимает остаток ширины и высоты экрана. Поле масштабируется колесом, щипком и кнопками, панорамируется перетаскиванием мышью (курсор grab) или пальцем. Ход, колода, легенда и действия хода — плавающие панели поверх поля.
- **Выбор на поле, подтверждение в панели.** Кондитер в «Круассане» ставится кликом по части нового тайла (тропа, пекарня, луг, сыроварня). Доступные части обведены пунктиром, участок под курсором подсвечивается целиком. Выбор — полупрозрачная фишка, клик по ней снимает выбор. Панель внизу только подтверждает («Поставить») или пропускает шаг («Без кондитера»).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Кнопки «Стать игроком» / «Стать наблюдателем» в сайдбаре | Решение пользователя: переключение — в самих списках |
| Показ пауз у партии без таймера (кнопка с ошибкой или заблокированная) | Заведомо бесполезная кнопка |
| Подсказки через атрибут `title` | Появляются с задержкой, выглядят системно |
| Форма настроек при создании комнаты | Комната создаётся с настройками по умолчанию, владелец меняет их в комнате |
| Плашка «Ждём места» с автоматическим входом | Пользователь выбрал окончательный отказ |
| Поле «Круассана» во весь экран, панель комнаты — выдвижной шторкой | Решение пользователя: сайдбар комнаты остаётся на месте |
| Участок кондитера — кнопками в панели хода | По подписи «Луг» не видно, какая часть тайла имеется в виду |
| Кнопка «Отменить» для выбранного участка | Решение пользователя: выбор снимается кликом по фишке на поле |
| Одна раскладка для всех досок | Растущему полю тайлов в колонке `max-w-5xl` достаётся малая часть экрана |

## Последствия

- Курсоры (`pointer`/`not-allowed`) и запрет `disabled:pointer-events-none` закреплены в правилах (`frontend/CLAUDE.md` §4).
