# Игры на фронте

Область: frontend · Диаграммы: [c4/3-frontend](../c4/3-frontend.md), [c4/3-frontend-portal](../c4/3-frontend-portal.md), [c4/3-backend-games](../c4/3-backend-games.md), [c4/dynamic/move](../c4/dynamic/move.md) · Код: `frontend/packages/game-core`, `packages/games/*`, `entities/game/model/registry.ts`

## Контекст

Правила игр живут только на сервере. Фронт должен показывать партию любой игры, не дублируя правила, а новые коды событий не должны требовать правок фронта. Игр будет много, и основной бандл расти не должен.

## Решение

- Фронт **не знает правил**: применяет патчи общим `applySessionEvent` и рисует только `moveOptions`. Единственное исключение — подсказки ввода пути по флагам `meta.advancedRules`.
- Состояние проверяется **guard'ами core и игры** (как устроено на бэкенде) на сгенерированных Zod-схемах, после снапшота и после каждого патча. Провал — переподключение.
- Ход отправляется конвертом `{type, data}` без версии. Последнее слово за сервером (422 `MOVE_REJECTED`).
- Игра — пакет `@qgames/game-<код>` (`{Board, PlayerCard?, isGameState}`), подключается только **динамическим `import()`**: каждая игра — отдельный чанк.
- **Список игроков на странице комнаты один**, данные игры об игроке (часы, цвет, ходящий, предложение ничьей) игра показывает **своей карточкой** `PlayerCard` поверх базовой из `@qgames/game-ui`. Список принимает реализацию карточки пропом и от игр не зависит; страница внедряет карточку партии через контекст (`GameSessionProvider` + `SessionPlayerCard`), код карточки игры — в её чанке.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Правила игры на фронте (симуляция состояния, проверка законности ходов) | Правила только на сервере |
| Редьюсер на каждый тип события (у игры и core) | Каждый новый код игры требует правок фронта |
| Ручные Zod-схемы состояния в пакете игры | Контракт дублировался руками и мог разойтись |
| Проверка состояния одной общей схемой (`SessionStateDto`) | Не повторяет устройство бэкенда (core + игра), не проверяет соответствие игре |
| `expectedVersion` в ходе | Версии партии больше нет, ход проверяет сервер по текущему состоянию |
| Свой список игроков у доски (часы, цвет) рядом со списком комнаты | Игроки дублировались; решение пользователя — один список с карточкой от игры |
| Карточка партии — компонент, собранный хуком на странице (`useMemo`) и переданный пропом | Компонент создаётся во время рендера, при смене партии карточки перемонтируются; выбран контекст |

## Последствия

- Отклик на ход приходит только после события сервера, локальной симуляции нет.
- Поля снапшота вне схемы отбрасываются (BACKLOG).
