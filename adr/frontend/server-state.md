# Серверные данные на фронте

Область: frontend · Диаграммы: [c4/3-frontend](../c4/3-frontend.md), [c4/dynamic/room-stream](../c4/dynamic/room-stream.md), [c4/dynamic/move](../c4/dynamic/move.md) · Код: `entities/room/model/use-room-events.ts`, `entities/session`

## Контекст

Данные комнаты приходят из ответов REST и из SSE-потока, состояние партии — только из потока. Две копии данных (кеш и стор) неизбежно разойдутся.

## Решение

- **TanStack Query — единственное место для серверных данных.** Ключи и функции берутся из Orval. Копировать данные в zustand или `useState` нельзя.
- **Комната:** события потока пишутся в кеш `GET /api/rooms/{id}` через `setQueryData`. Мутации, возвращающие комнату, кладут ответ в кеш, а не перезапрашивают.
- **Партия:** состояние хранится в кеше Query под ключом `['session-stream', sessionId]`. Это исключение из правила «ключи только из Orval»: у потока нет GET-ручки. Опроса нет.
- Ответы 4xx запросы не повторяют.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Опрос комнаты (раз в 2 с или во время партии) | Задержка и лишние запросы; ответы перетирали кеш без сверки |

## Последствия

- Есть гонка ответа `GET` комнаты и событий потока (BACKLOG «Гонка ответа GET комнаты»).
