# Серверные данные на фронте

Область: frontend · Диаграммы: [c4/3-frontend](../c4/3-frontend.md), [c4/dynamic/room-stream](../c4/dynamic/room-stream.md), [c4/dynamic/move](../c4/dynamic/move.md) · Код: `entities/room/model/use-room-events.ts`, `entities/session`

## Контекст

Данные комнаты приходят из ответов REST и из SSE-потока, состояние партии — только из потока. Две копии данных (кеш и стор) неизбежно разойдутся, а два источника одной копии (REST и поток) гоняются между собой.

## Решение

- **TanStack Query — единственное место для серверных данных.** Ключи и функции берутся из Orval. Копировать данные в zustand или `useState` нельзя.
- **Комната на странице — только из потока:** кеш `['room-stream', roomId]` (снапшот `{seq, room}`, затем патчи по seq общим `applyPatch`). Мутации комнаты отвечают 204, изменение приходит событием. `GET` комнаты (лоадер маршрута) комнату не показывает: он для ошибок и перечитывается после закрытия потока сервером.
- **Партия:** состояние хранится в кеше Query под ключом `['session-stream', sessionId]`. Опроса нет.
- Ключи потоков — исключение из правила «ключи только из Orval»: у потоков нет GET-ручки.
- Ответы 4xx запросы не повторяют.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Опрос комнаты (раз в 2 с или во время партии) | Задержка и лишние запросы; ответы перетирали кеш без сверки |
| События потока в кеш `GET` комнаты, ответы мутаций туда же (`setRoomCache`), `staleTime: Infinity` против фонового перезапроса | Ответ `GET` или мутации мог прийти позже события и затереть кеш более старыми данными |

## Последствия

- Гонки ответа `GET` и событий потока нет: `GET` в кеш потока не пишет.
- До снапшота страница показывает «Загружаем комнату…».
