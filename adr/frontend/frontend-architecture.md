# Архитектура кода фронта

Область: frontend · Диаграммы: [c4/3-frontend](../c4/3-frontend.md) · Код: `frontend/apps/*/src`, `frontend/packages/config/eslint/fsd.js`

## Контекст

Код приложений должен расти без клубка зависимостей между фичами, а границы должны проверяться автоматически, а не на ревью.

## Решение

- **Feature-Sliced Design:** слои `app` → `pages` → `widgets` → `features` → `entities` → `shared`, импорт только вниз. Слайс доступен снаружи только через `index.ts`.
- Роутинг (`src/routes/`) живёт отдельно от слоёв: в роуте только объявление и подключение страницы.
- Общее для нескольких приложений выносится в `packages/*`.
- Границы проверяет `eslint-plugin-boundaries`.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Type-sliced структура (как на бэкенде) | Границы между фичами ничем не защищены |
| Feature-folders | Слабее FSD по правилам зависимостей |

## Последствия

- Больше файлов `index.ts` и иногда спор, в какой слой положить код.
- Подробные правила (сегменты, алиасы, имена файлов) — `frontend/CLAUDE.md` §3.
