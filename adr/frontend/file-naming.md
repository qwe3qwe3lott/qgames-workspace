# Именование файлов и папок фронтенда

Область: frontend · Диаграммы: — · Код: `frontend/packages/config/eslint/index.js` (`check-file`)

## Контекст

Фронтенд называл файлы в kebab-case (как генерирует shadcn), бэкенд — по имени класса. Нужен один принцип для обоих репозиториев, при этом по имени файла должно быть видно, компонент в нём или нет.

## Решение

- **Имя файла — по главному экспорту**, как на бэкенде: компонент — PascalCase (`HomePage.tsx`), остальное — camelCase (`useRoomEvents.ts`, `errorMessages.ts`). Сопутствующие файлы повторяют имя компонента (`HomePage.testIds.ts`).
- **Папки — camelCase** (`pages/notFound`, `features/createRoom`), папка компонента — PascalCase (`NotFoundPage/NotFoundPage.tsx`, вводится, когда у компонента появляются свои файлы).
- **shadcn-компоненты** `@qgames/ui` тоже PascalCase (`Button.tsx`); после `shadcn add` файл переименовывается вручную.
- **Исключения:** `src/routes/` (имя файла — сегмент URL, конвенции TanStack Router), сгенерированный код, конфиги инструментов, каталоги и имена npm-пакетов (`packages/game-ui`, `@qgames/game-ui`: npm разрешает только строчные).
- Правило проверяет ESLint (`eslint-plugin-check-file`).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| kebab-case везде (как shadcn) | Расходится с бэкендом; по имени не отличить компонент от модуля |
| PascalCase для всех файлов | Непривычно для TS-модулей с функциями (`UseRoomEvents.ts`), компонент снова не отличить по имени |
| shadcn-компоненты оставить в kebab-case | Исключение из правила ради CLI; переименование после `shadcn add` дешевле |
| Каталоги пакетов в camelCase (`packages/gameUi`) | Каталог расходится с именем npm-пакета, которое обязано быть строчным |

## Последствия

- Один принцип с бэкендом; нарушения ловит `pnpm lint`.
- Каждый `shadcn add` требует ручного переименования файла и импортов.
- Windows не различает регистр: смена только регистра (`header.tsx` → `Header.tsx`) делается `git mv` в два шага через временное имя.
