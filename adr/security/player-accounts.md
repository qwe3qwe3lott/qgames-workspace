# Аккаунты игроков и способы входа

Область: backend, frontend · Диаграммы: [c4/3-backend-auth](../c4/3-backend-auth.md), [c4/dynamic/auth](../c4/dynamic/auth.md), [erd/user-auth](../erd/user-auth.md) · Код: `LoginService`, `LoginRules`, `features/auth`

## Контекст

Портал не шлёт писем и не может сам подтвердить личность, но ботов нужно отсекать. Логин станет адресом страницы пользователя. Другие игроки не должны видеть настоящее имя.

## Решение

- **Регистрация только через внешнего провайдера** (сейчас Google, позже VK и др.). На шаге регистрации игрок сам выбирает логин и, по желанию, пароль. Email не хранится.
- Google: фронт получает ID token через скрипт GIS, бэкенд проверяет подпись по JWKS. Непривязанный аккаунт получает 404 `REGISTRATION_REQUIRED`, автосоздания нет.
- **Логин** уникален и **неизменяем**. **Ник** неуникален, сначала равен логину. Ник и аватар меняются одной `PATCH /profile`.
- Вход по логину и паролю (пароль задаётся при регистрации или в профиле). Сброса пароля нет: игрок входит через Google и меняет пароль. Пароли хранятся в Argon2id.
- Способы входа привязываются **только явно** из профиля.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Google Authorization Code flow на бэкенде | Редиректы, хранение state/PKCE на сервере, сложнее |
| BCrypt | Слабее против GPU-перебора, ограничение в 72 байта |
| Автопривязка Google по email | Аккаунты создаёт только провайдер, подтверждать email у нас нечем |
| Email в модели аккаунта | Не у всех провайдеров есть подтверждённый email; почту мы не подтверждаем |
| Вход по паролю через email | Email убран из модели; логин короче и станет адресом страницы |
| Регистрация по логину и паролю без провайдера | Нужно подтверждать личность, иначе ботов не отсечь |
| Изменяемый логин | Логин — адрес страницы и субъект входа по паролю, смена ломала бы ссылки |
| Уникальный ник | Игроки различаются по id, уникален логин |
| Ник из профиля Google (`given_name`) | Другие игроки видели бы настоящее имя |
| Аккаунт первым входом через Google со сгенерированным ником `player-xxxxxx` | Уникальный неизменяемый логин должен выбрать сам игрок |
| Отдельная ручка смены только ника | Аватар тоже меняется |
| `@react-oauth/google` на фронте | Runtime-зависимость и провайдер на всё приложение ради одной кнопки |

## Последствия

- Один человек может завести несколько аккаунтов через разных провайдеров — принятый риск.
- Без `GOOGLE_CLIENT_IDS` и `PUBLIC_GOOGLE_CLIENT_ID` регистрация недоступна (локальная настройка — `frontend/docs/docker.md`).
