# Настройка и защита VPS

Область: система · Диаграммы: [c4/deployment](../c4/deployment.md) · Код: `server/` воркспейса (`deploy.sh`, `certbot-deploy-hook.sh`)

## Контекст

Сервер получен с входом root по паролю на порту 22. Веб-консоли (VNC) у провайдера нет: потеря SSH-доступа означает потерю сервера. Памяти 1 ГБ, на защиту её почти не остаётся. CI должен заходить на сервер, но не получать полный доступ.

## Решение

- **SSH:** порт 52022 (22 закрыт), только по ключу (`PasswordAuthentication no`, `KbdInteractiveAuthentication no`). Root входит по ключу (`PermitRootLogin prohibit-password`), отдельного sudo-пользователя нет. Настройки — drop-in `/etc/ssh/sshd_config.d/10-qgames.conf`; у Ubuntu 24.04 порт берёт `ssh.socket` через генератор из sshd_config.
- Правки sshd и firewall — только с проверкой нового входа, пока прежняя сессия открыта (смена порта — в два шага: 22 + 52022, затем только 52022).
- **ufw:** входящие только 52022 (`limit`), 80, 443. Docker публикует порты в обход ufw, поэтому опубликован только web (80, 443).
- **CI:** пользователь `deploy` (группа docker, пароль заблокирован), его ключ в `authorized_keys` с `command="/opt/qgames/bin/deploy.sh",restrict`.
- **Обслуживание:** unattended-upgrades (обновления безопасности), swap 1 ГБ (`vm.swappiness=10`), журнал systemd ≤ 100 МБ, логи контейнеров `json-file` 10 МБ × 3, выключены лишние службы (multipathd, ModemManager, udisks2, packagekit).
- **TLS:** certbot на хосте, сертификат на оба имени; продление по systemd-таймеру через webroot `/opt/qgames/acme` (его отдаёт web на :80), deploy-hook копирует сертификат в `/opt/qgames/certs` и перечитывает nginx.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Запрет входа root, отдельный sudo-пользователь | Нет консоли провайдера: ошибка с sudo-пользователем отрезает сервер — решение пользователя |
| Вход по паролю как запасной | Пароль можно перебирать |
| fail2ban | ~40 МБ RAM; при входе только по ключу перебор бессмыслен, ufw `limit` хватает |
| Стандартный порт 22 | Решение пользователя: меньше шума от ботов |
| certbot в контейнере compose | Нужен доступ к docker для reload nginx; постоянный контейнер ест память |
| DNS-01 через DuckDNS | У DuckDNS одна TXT-запись на домен — два имени в одном сертификате ненадёжны |

## Последствия

- **Запасного ключа нет** (решение пользователя): потерян ключ или фраза — потерян сервер. Задача в BACKLOG.
- Сеть пользователя идёт через VPN (Karing): проверки доступности с его машины недостоверны, их делаем с сервера или с телефона.
