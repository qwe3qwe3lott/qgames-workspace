# Часы партии

Область: backend, frontend · Диаграммы: [c4/3-backend-game](../c4/3-backend-game.md), [c4/3-frontend](../c4/3-frontend.md) · Код: `backend/games/game-core/.../Timer.kt`, `frontend/packages/game-ui/src/components/Clock.tsx`

## Контекст

Партии с таймером нужен один общий для всех игр вид часов: запас на всю партию плюс добавочное время. Официальные контроли (пресеты простых правил) — с инкрементом Фишера. Части игроков нужна задержка: в начале хода сначала идёт время на ход, потом запас. Пауза не должна давать лишнего времени, сколько бы раз её ни ставили.

## Решение

- `TimeControl {baseSeconds, bonusType: INCREMENT | DELAY, bonusSeconds}`, `null` — без таймера. Оба вида разрешены всем играм.
  - **Инкремент** (Фишер): после своего хода игрок получает `bonusSeconds` к запасу. Дедлайн — начало хода + запас.
  - **Задержка** (простая): дедлайн — начало хода + запас + `bonusSeconds`. После хода у игрока остаётся `min(запас, остаток)`, неистраченная задержка не копится.
- Simple-правила (пресеты) всегда дают инкремент. Задержка выбирается только в advanced. Пресет времени в advanced-форме переключает вид на инкремент.
- **Пауза — по меткам времени:** `pausedAt` и `deadline` — моменты, остаток на паузе — `deadline − pausedAt`, продолжение сдвигает дедлайн ровно на `now − pausedAt`. Задержка входит в дедлайн и при продолжении заново не начисляется. Поэтому серия «пауза → продолжение» времени не добавляет (тест `repeated pause and resume give no extra time`).
- Новых полей в состоянии нет: фронт выводит зоны из `deadline`, `remainingMs` и вида из настроек партии. `Clock` при задержке показывает `[запас │ задержка]`: у ходящего сначала идёт правая зона, у остальных она полная и серая. При инкременте зона одна, инкремент прибавляет сервер.
- В интерфейсе: «Часы», вид — «Инкремент» / «Задержка», в описании комнаты — «10 мин + 5 с инкремент».

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Только инкремент Фишера (было изначально) | Пользователю нужна и задержка: время на ход, которое тратится первым |
| Только задержка (было недолго) | Официальные контроли и простые правила — с инкрементом |
| Задержка Бронштейна (после хода возвращается потраченное, не больше N) | Итог тот же, что у простой задержки, но запас убывает сразу, и отдельной зоны задержки не показать |
| Два поля `incrementSeconds` и `delaySeconds` | Можно задать оба сразу, нужна проверка «одно из двух»; вид + секунды проще |
| Подпись «+N с за ход» под часами | Непонятна, пользователь попросил убрать |

## Последствия

- Двухэтапные контроли (N ходов за время) часы не выражают.
