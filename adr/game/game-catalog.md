# Каталог игр и доступность игры

Область: backend, frontend · Диаграммы: [c4/3-backend-game](../c4/3-backend-game.md), [erd/game](../erd/game.md) · Код: `GamePublishStatus`, `GameCatalogVerifier`, `GameService.checkAccessible`, `NotPublishedGameCleanupJob`

## Контекст

Игры появляются постепенно: одни в разработке, другие нужно скрыть из списка с доступом по ссылке, третьи — отключить. Фронту не нужно знать про режимы, ему важно только, доступна ли игра.

## Решение

- Игры — строки таблицы `game` (DML-миграции), набор кодов совпадает с enum `GameCode`. `GameCatalogVerifier` при старте сверяет набор кодов и наличие модулей правил.
- **Три статуса публикации:** `PUBLISHED` (в каталоге), `HIDDEN` (только по ссылке), `NOT_PUBLISHED` (в разработке или отключена: 404 `GAME_NOT_FOUND`, комнаты удаляет `NotPublishedGameCleanupJob`).
- Статус **наружу не выходит**: в ответах только доступные игры, недоступная игра — 404.
- Каталог открыт гостям (`GET /api/games`, `GET /api/games/{gameCode}`). Комнаты требуют входа.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Флаг `disabled` у игры | Нужно ещё и скрыть игру из списка, оставив доступ по прямой ссылке |
| Статусы `DISABLED` (запрет новых комнат) и `FORCE_DISABLED` (отключение с удалением комнат) наряду с `NOT_PUBLISHED` | Решение пользователя: лишние режимы недоступности |
| Поле `publishStatus` в ответах, 409 `GAME_UNAVAILABLE` | Решение пользователя: наружу выходят только доступные игры, статус фронту не нужен |
| Статус `ANNOUNCED` («скоро выйдет») | Убран пользователем |

## Последствия

- Отключение игры удаляет её комнаты и историю партий.
- Гость с протухшей access-кукой получает на ручках каталога 401 (Bearer-фильтр проверяет токен и на permitAll). Принято осознанно.

## Открытые вопросы

- Решить при управлении каталогом в админке: проверка модуля правил в ручке смены статуса, судьба периодического `NotPublishedGameCleanupJob`.
