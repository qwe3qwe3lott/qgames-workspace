# Жизнь комнаты: вход, выход, владение, удаление

Область: backend, frontend · Диаграммы: [c4/3-backend-game](../c4/3-backend-game.md), [c4/dynamic/room-stream](../c4/dynamic/room-stream.md), [erd/game](../erd/game.md) · Код: `RoomService`, `EmptyRoomCleanupJob`, `RoomRepository.lockById`

## Контекст

Комната — общее пространство участников. Она должна жить, пока в ней кто-то есть, всегда иметь управляющего, если есть присутствующие, и не терять игроков идущей партии из-за перезагрузки страницы. Мутации конкурируют между собой (вход, выход, ход, джобы).

## Решение

- Все мутации комнаты, участников и партии сериализует **блокировка строки комнаты**. Исключение — смена ника без блокировки.
- Комната создаётся пустой, первый вошедший становится игроком и владельцем.
- **Выход мгновенный**, таймеров выхода нет. Игроки идущей партии закреплены до её конца (`left_at`), последствия их отсутствия решает игра.
- **Владение** при уходе владельца сразу получает случайный присутствующий игрок, затем наблюдатель. Отсутствующие игроки владельцами не становятся. Владелец может передать владение сам.
- **Лимит наблюдателей** — настройка комнаты (`settings.room.maxSpectators`, 0–12, по умолчанию 8, [room-settings](room-settings.md)). Новичок без места игрока и места наблюдателя не входит (409 `NO_SPECTATOR_SEAT`), на фронте это окончательный отказ до перезагрузки страницы. Игрок в наблюдатели — тоже только при свободном месте. Понижение лимита вошедших не выводит. Игрок партии возвращается всегда.
- Пустая комната (нет присутствующих) удаляется через 30 минут. Ручного удаления нет.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Игрок только в одной ожидающей комнате | Лишнее ограничение |
| Владелец не может выйти / его выход удаляет комнату | Комната должна жить, пока в ней кто-то есть |
| Пустую комнату наследует прежний владелец | Решили отдавать первому вошедшему |
| Прерывать партию, если вышел её игрок | Игрок должен иметь возможность вернуться |
| Автоудаление по неактивности | Решили считать пустоту, а не активность |
| Пустая комната = без игроков | Наблюдатели тоже держат комнату |
| Отложенный выход со сроками по ролям + `RoomLeaveJob` + заморозка сроков на паузе | Срок наблюдателя не переживал перезагрузку, сроки множились по ролям и усложняли паузу |
| Таймер выхода у участников (15 с / 1 мин); льготный срок выхода на фронте | Пользователь выбрал модель без таймеров; перезагрузка всё равно теряла место наблюдателя |
| Отдельный `connect-grace` для создателя комнаты | Лишняя настройка |
| Блокировать комнаты при смене ника | Пропущенная смена ника некритична |
| Передавать владение отсутствующему игроку партии | Владельцем на время становился отсутствующий |
| Окно владения 15 с + `RoomOwnerGraceJob` | Колонки, джоб и ветки во входе; пока окно шло, командовать было некому |
| Передавать владение самому раннему игроку | Пользователь выбрал случайный выбор |
| Удаление комнаты владельцем | Выкидывает остальных участников и стирает историю партий; хватает автоудаления |
| Вход без лимита наблюдателей | Пользователь ввёл лимит в настройках комнаты |
| Выводить наблюдателей сверх пониженного лимита | Вошедшие сидят, пока не уйдут сами |
| Ждать места и входить автоматически (переподключение потока) | Пользователь выбрал окончательный отказ |

## Последствия

- Перезагрузка вне партии — это выход и новый вход: при занятых местах игрок вернётся наблюдателем.
- Партия без присутствующих игроков идёт до удаления комнаты (BACKLOG «Партия без игроков»).
