# Стадии партии

Область: backend, frontend · Диаграммы: [c4/3-backend-games](../c4/3-backend-games.md) · Код: `backend/games/game-core/.../Stages.kt`, `SessionEngine.kt`, `Timer.kt`, `backend/games/checkers-game`, `frontend/packages/game-core/src/core.ts`, `frontend/apps/portal/src/widgets/gameBoard`

## Контекст

Партия была одной сплошной игрой: `GameRules.start` один раз задавал состояние и очерёдность, часы шли на всю партию. Всё, что идёт «до игры» (кто ходит первым, выбор цвета), приходилось зашивать в игру или решать случайно по seed. Нужны куски партии со своей механикой ходов, очерёдностью (по очереди, одновременно, кто первый) и часами (на ход, на стадию, без часов) при общем списке игроков.

## Решение

- **Стадиями управляет сама игра.** `GameRules` один. Код текущей стадии лежит в `state.stage` — это блок core, у игры из одной стадии он `play`. Переход игра выдаёт из `decide` или `onTimeout` хелпером `Stages.changed(GameStart)`. Классы состояния, хода и полей игрока игра отдаёт по стадии (`gameStateClass(stage)`, `moveClass(stage)`, `playerClass(stage)`).
- **`state` — состояние текущей стадии.** Переход — событие `stage-changed` = `PUT ["state"]`: новая стадия, поля игры и игроков, очерёдность. Часов и итога нет, варианты ходов пусты. Прошлые стадии остаются только в журнале. Пути событий игры не меняются (от `state`). Маскируется `stage-changed` так же, как начальное состояние.
- **Часы при переходе ставит движок.** Следом за переходом `SessionEngine` дописывает `timer-started` (часы новой стадии по `GameRules.timer(settings, stage)`) и `move-options-changed`. Игра времени не знает. В наборе событий допускается не больше одного перехода, он идёт последним событием игры и не сочетается с концом партии.
- **Общий отсчёт стадии** — `timer.kind = STAGE`: один дедлайн на всю стадию, `clocks` пуст. У часов игроков `kind = PLAYERS`. Пауза, остановка и `MoveTimeoutJob` работают по тому же `deadline`. На фронте общий отсчёт показывается над доской (`StageCountdown`), а не в карточке игрока.
- **seed — в `decide` и `onTimeout`** (серверный `room_session.seed`, клиенту не уходит): случайность при переходе стадии (цвета по таймауту) остаётся воспроизводимой.
- **Склейки игр нет.** Чужая игра стадией не берётся. Мини-стадии («кто раньше выберет») переиспользуются копированием между играми.
- **Шашки:** `colorAssignment: RANDOM | FIRST_PICK` в simple и advanced (по умолчанию RANDOM). FIRST_PICK начинает партию со стадии `color-pick`: `PICK_COLOR` доступен обоим игрокам, очереди нет, общий отсчёт 30 с (константа, действует и без часов партии). Первый нажавший получает свой цвет, соперник — противоположный. По таймауту цвета распределяются случайно по seed. Опоздавший выбор отклоняется с 422 `COLOR_ALREADY_PICKED`, фронт его не показывает (`GameModule.staleMoveReasons`).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Стадия — свой `StageRules` в core, игра описывает граф стадий, переключает движок | Больше платформы; склейка игр, ради которой он нужен, не планируется |
| Линейная цепочка стадий (выход i-й — вход (i+1)-й) | Тот же отдельный контракт стадий, а гибкость нужна внутри игры |
| Модули стадий `games/stages/*` или реестр стадий по коду для склейки игр | Склеивать игры не планируем, мини-стадии копируются |
| Поддерево на стадию (`state.stages[]`) | Пути событий стадии зависят от индекса, движку пришлось бы их переписывать |
| Игра сама строит часы новой стадии (`now` в `decide`) | Логика часов дублируется в каждой игре |
| Отсчёт стадии как пустые `clocks` без `kind` | Неявный смысл |
| Время стадии выбора цвета — настройка; стадия без часов | Пользователь выбрал константу 30 с, затем случайные цвета |
| Выбор цвета только в advanced | Выбор цвета понятен казуальным игрокам: поле есть и в simple |

## Последствия

- Новая стадия игры = ветка `decide`/`onTimeout`/`moveOptions` по `state.stage`, класс её состояния, DTO-вариант `SessionStateDto` и ветка разбора снапшота (`SessionEventResponseMapper.stateClass`). На фронте Board игры выбирает UI по стадии, guard проверяет поля стадии.
- Пакет игры на фронте не знает другие стадии, кроме своих. Портал знает только `stage` как строку и `timer.kind`.
