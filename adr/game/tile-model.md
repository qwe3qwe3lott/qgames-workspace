# Модель тайла и его рисунок

Область: backend, frontend · Диаграммы: [c4/3-backend-games](../c4/3-backend-games.md) · Код: `backend/games/croissant-game/.../CroissantTiles.kt`, `frontend/packages/games/croissant/src/lib/tileGeometry.ts`

## Контекст

Тайлы «Круассана» бывают с несколькими независимыми тропами (дуги W-N и S-E), с раздельными пекарнями на соседних
сторонах и с тропами, которые входят в конкретный элемент тайла. Модель должна это описывать, а фронт — рисовать
по ней без геометрии в коде под каждый тип. Как тайл живёт в партии — [tile-network](tile-network.md).

## Решение

- **Тайл — перечень элементов**: `edges`, пекарни (вывеска), тропы, постройка в центре (`structures`), луга
  (полуребра и `adjacentBakeries`).
- **`edges` — единственный источник сторон**: объект `{N, E, S, W}`, на каждой стороне `{type, index}`, то есть
  пекарня, тропа или луг и индекс в их списке. У пекарен и троп своих сторон нет: на стороне строго один элемент.
- **Постройка — `structures {garden, dairy}`**, не обе сразу. Сыроварня — участок для кондитера, сад только обрывает
  тропы, луга постройки не делят. Рисуется в центре.
- **Тропа на две стороны и больше соединяет их; тропа на одну сторону входит ровно в одну цель**: в пекарню
  (`bakeryIndex`) или в постройку тайла (`structure`). Развилка и перекрёсток — отдельные тропы до сада.
- **Смежность луга с пекарнями — по куску на тайле** (`adjacentBakeries`). Сеть склеивает куски луга по всем тайлам и
  собирает пекарни луга целиком, итог считает завершённые среди них.
- **Каталог проверяется при загрузке** (`CroissantTileType.init`): индексы рёбер, у пекарни и тропы есть сторона,
  цели троп, `garden` и `dairy` не вместе. Полуребра лугов покрывают стороны без пекарен ровно один раз. Оба
  полуребра стороны-луга принадлежат лугу её индекса.
- **Фронт рисует тайл гранями плоского графа**: край плитки, кромки пекарен (купол у одной стороны, диагональ у
  угловой) и линии троп (прямая, дуга мимо центра, отрезок к цели). Грань с краем пекарни — пекарня, с полуребрами
  луга — луг; по граням же выбор кондитера и точка фишки. Раздельные пекарни — разные купола, касаются только углом.
  Геометрия считается в базовой ориентации и кешируется по коду типа, поворот — transform группы.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Тайл из 8 треугольников, тропы из центра | Независимые тропы сходятся в центре, раздельные пекарни сливаются в угловую |
| Стенка между раздельными пекарнями | Пекарни всё равно выглядят одной фигурой |
| Развилка — одна тропа на 3–4 стороны | Ветки не завершаются по отдельности |
| Тупик тропы в центре без элемента | Неявная цель; сад — явный элемент, который рисуется |
| Цель тропы объектом `end {kind, bakery}` | Лишняя вложенность; плоские поля проще |
| Координаты рисунка в каталоге | Ручная геометрия на каждый тип; форма выводится из модели |
| `sides` у пекарни и тропы вместе с `edges` | Одно и то же хранится дважды и может разойтись |
| `edges` списком по ordinal или `Map` | Список — неявный порядок сторон; `Map` в OpenAPI даёт `Record<string>` без обязательных ключей |
| Постройки списком `{type, placement, placementIndex}` | Пока не нужно: место сыроварни не влияет на правила, сад — только тупик тропы |
| Смежность луга выводить из геометрии (углы сторон) | Рисунок будущих тайлов обязан был бы следовать правилу углов |

## Последствия

- Новые формы тайлов — только данные каталога: правила и рисунок их подхватывают.
- Модель и рисунок сверяются тестами: грани каждого типа каталога совпадают с его пекарнями и лугами
  (`tileGeometry.test.ts` на снимке каталога). Ошибка в лугах каталога видна как лишняя или слитая грань.
- Снимок карточки игры в тестах и Storybook фронта (`assets.fixture.json`: каталог и модули) обновляется скриптом
  `pnpm --filter @qgames/game-croissant assets:fetch` при правке каталога.
