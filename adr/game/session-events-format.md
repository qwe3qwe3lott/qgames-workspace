# Формат событий партии и комнаты

Область: backend, frontend · Диаграммы: [c4/3-backend-games](../c4/3-backend-games.md), [c4/dynamic/move](../c4/dynamic/move.md), [c4/dynamic/room-stream](../c4/dynamic/room-stream.md) · Код: `backend/libs/doc-patch` (`DocumentPatch`), `backend/games/game-core` (`SessionEvent`), `frontend/packages/doc-patch` (`applyPatch`)

## Контекст

События партии должны строить состояние на сервере и на фронте, маскироваться для разных зрителей, переигрываться и не требовать правок фронта при каждой новой игре. Комнату на странице строили REST-ответы и события-замены потока вперемешку: ответ `GET` или мутации мог прийти позже события и затереть кеш более старыми данными, а диспетчер потока читал данные при раздаче, а не в момент изменения.

## Решение

- Событие — **патч документа** `{status, meta, state}`: `method` (`PUT`, `PATCH`, `DELETE`, `INFO`) + `path` + `value` и говорящий `code` только для журнала.
- **Один общий применитель** на сервере (`DocumentPatch`, `libs/doc-patch`) и на фронте (`applyPatch`, `@qgames/doc-patch`) с одинаковой семантикой: для партии и для комнаты. Своих редьюсеров нет ни у игр, ни у комнаты. Сценарии применителя одинаковы на обеих сторонах (`DocumentPatchScenariosTest`, `patch.test.ts`).
- Путь — сегменты: строка — ключ, `{id}` — элемент массива по id. Коллекции хранятся массивами объектов с `id`.
- `PATCH` — неглубокое слияние, `null` — это значение. Одно событие — одна операция.
- Первое событие — `session-started` = `PUT []` с начальным документом. Перед концом и отменой часы переходят в `STOPPED`.
- Пауза — статус таймера (`game-paused`/`game-resumed`), а не партии. `moveOptions` лежат внутри объекта игрока.
- **Поток комнаты — в том же формате:** документ — комната (`RoomResponse`), первое сообщение `snapshot {seq, room}`, дальше патчи по seq (`room.event_seq`). Комнату на странице строит только поток, мутации комнаты отвечают 204 ([dynamic/room-stream](../c4/dynamic/room-stream.md)).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Типизированные события (`started`, `turns-changed`, `moved`…) + `evolve` у каждой игры, редьюсер на каждый тип на фронте | Каждый новый код игры требует правок на обеих сторонах |
| Пауза на уровне сессии (`session-paused`, статус `PAUSED`) | В играх без таймера пауз нет |
| JSON Pointer с индексами массивов (RFC 6902) | Индексы хрупкие: сдвиг массива — и маскированный клиент расходится с сервером |
| Коллекции как объекты по id (`players: {u1: …}`) | Меняется форма состояния, порядок живёт отдельно |
| Список операций в одном событии (`ops: [...]`) | Грубее детализация кодов |
| Глубокое слияние PATCH (RFC 7386, `null` удаляет) | Конфликтует с nullable-полями, дублирует DELETE |
| Событие без метода для информационных кодов | Неявный контракт |
| Таймер `RUNNING` после конца партии | Финальное состояние не самодостаточно для повтора |
| Начальное состояние функцией вне журнала | Скрытые данные пришлось бы маскировать в самом состоянии — тот же отдельный view |
| `moveOptions` списком на верхнем уровне состояния | В полном состоянии варианты разных игроков смешались бы |
| Поток комнаты событиями-заменами частей без seq (`users-changed`, `settings-changed`, `session-changed`) + `GET` и ответы мутаций в тот же кеш | Ответ `GET`/мутации мог затереть более новое событие; данные читались при раздаче, а не при изменении (флак порядка событий в тестах) |
| Журнал событий комнаты в таблице (`room_event`) | Лишняя таблица и чистка: патчи комнаты маленькие и целиком помещаются в payload NOTIFY |
| Применитель только в game-core (общий пакет игр) | Комната не игра: применитель — отдельные пакеты `doc-patch` |

## Последствия

- Новая игра не меняет ни контракт событий, ни фронтовый применитель. Новые коды дописываются только в описание (`SessionEventCodes.DESCRIPTION`).
- Коды комнаты — `RoomEventCodes` (game-api). Payload NOTIFY ограничен 8000 байт: больше — ошибка публикации.
- `value` в OpenAPI не типизирован, поэтому корректность состояния на фронте проверяют guard'ы ([frontend-game-logic](../frontend/frontend-game-logic.md)).
