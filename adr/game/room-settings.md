# Настройки комнаты: room, simple и advanced

Область: backend, frontend · Диаграммы: [c4/3-backend-games](../c4/3-backend-games.md), [erd/game](../erd/game.md), [c4/3-frontend-portal](../c4/3-frontend-portal.md) · Код: `backend/games/game-core/.../GameRules.kt`, `RoomService.updateSettings`, `RoomSettingsValidator`, `frontend/apps/portal/src/entities/room/model/settings.ts`

## Контекст

Правила игр бывают сложными. Чтобы не нагружать новых и казуальных игроков, нужен короткий простой выбор (вариант, «блиц»). Для гибкости нужна возможность напрямую менять часть продвинутых настроек (свои часы, отключить турецкий удар). Кроме правил игры, у комнаты есть свои настройки (лимит наблюдателей), и их нужно менять и во время партии. Партия должна зависеть от одного полного набора правил.

## Решение

- Настройки — три группы `{room, simple, advanced}`:
  - **room** — сама комната (`maxSpectators`, 0–12, по умолчанию 8). Меняется в любой момент.
  - **advanced** — корневые правила: по ним идёт партия, её снимок пишется в `room_session.settings` и в `meta.game.settings`. Часы — общий блок `TimeControlDto {enabled, baseSeconds, incrementSeconds}`.
  - **simple** — простые правила, чтобы не нагружать новых и казуальных игроков (вариант + пресет времени игры). Из него бэкенд выводит advanced (`GameRules.toAdvanced`).
- simple и advanced — **взаимоисключающий режим** комнаты. В ответе advanced есть всегда, simple = null означает advanced-режим. Обе группы меняются только между партиями, все их поля обязательны.
- Какие правила владелец задаёт в advanced, решает игра. Остальное выводится из advanced (`GameRules.advancedRules` → `meta.advancedRules`). Например, у шашек доска и первый ход выводятся из варианта.
- Пресеты времени — свои у каждой игры (enum `CheckersTime`, `NothingTime`), общего типа нет.
- Одна ручка `PUT …/settings {room?, simple?, advanced?}`: переданная группа заменяется целиком. simple и advanced вместе передать нельзя.
- Перевод simple → advanced делает бэкенд (`POST /api/games/{gameCode}/advanced-settings`). Фронт вызывает его при включении галочки «Продвинутые правила». Без галочки отправляется simple.
- Комната создаётся без настроек — с `defaultSettings` игры (simple-режим).
- Хранение — один json `room.settings`, без отдельных колонок.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Плоские `timeControl` + `gameSettings`, меняются только между партиями | Нет быстрого выбора и тонкой настройки, лимит наблюдателей нельзя менять в партии |
| Лимит наблюдателей отдельным полем рядом с прежними настройками | Пользователь выбрал общую модель групп |
| Advanced как nullable-переопределения поверх simple | Каждому полю нужен третий вариант «по умолчанию»; пользователь выбрал взаимоисключающие режимы |
| Фронт сам выводит advanced из simple по таблицам с бэкенда | Правила вывода дублируются на фронте; перевод делает бэкенд |
| Всегда полное тело PUT, simple/advanced сверяются с текущими | Лишняя сверка; группы опциональны |
| Отдельные колонки (`room.max_spectators`) | Решили держать настройки одним json |
| Общий enum пресетов времени | Пресеты у игр разные |
| Настройки при создании комнаты | Создатель меняет их уже в комнате |

## Последствия

- Новая игра задаёт simple, advanced, `toAdvanced`, `clock` и при необходимости `advancedRules` (чек-лист — `backend/games/CLAUDE.md`).
- В advanced-режиме прежний simple не хранится: после выключения галочки форма показывает simple по умолчанию.
- Ошибки ручки перевода приходят без префикса `simple.`, поэтому форма показывает их общим текстом, а simple проверяет до запроса.
