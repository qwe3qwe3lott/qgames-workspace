# Присутствие в комнате

Область: backend, frontend · Диаграммы: [c4/dynamic/room-stream](../c4/dynamic/room-stream.md), [erd/game](../erd/game.md) · Код: `room_connection`, `RoomConnectionHeartbeatJob`, `RoomConnectionCleanupJob`, `useRoomPresence.ts`

## Контекст

Нужно знать, кто сейчас в комнате, чтобы раздавать места, передавать владение и удалять пустые комнаты. Браузер ненадёжно сообщает об уходе: запросы при закрытии вкладки теряются, процесс сервера может упасть.

## Решение

- **Присутствие = открытый SSE-поток комнаты.** Ручек входа и выхода нет: открытие потока — вход, закрытие последнего потока пользователя — выход.
- Каждое подключение — строка `room_connection` с **арендой 20 с**. Подключений у пользователя может быть несколько (вкладки, устройства).
- `RoomConnectionHeartbeatJob` **раз в 5 с** шлёт ping и продлевает аренду. Обрыв замечается по неудачной записи ping. `RoomConnectionCleanupJob` удаляет протухшие подключения.
- События потока комнаты — патчи с seq (`room.event_seq`), как у партии ([session-events-format](session-events-format.md)): снапшот несёт seq, подписчик отбрасывает события не новее снапшота. Вход и выход — `member-joined`, `member-left`, `member-leaving`/`member-returned`, владение — `owner-changed`.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Ручки `join`/`leave` (выход keepalive-запросом на `pagehide`, автовход по опросу) | Запросы теряются при закрытии вкладки, а поток событий и так нужен |
| Кнопки «Войти в комнату» и «Выйти из комнаты» | Лишние действия; без выхода комната не пустела |
| Одно подключение на пользователя (новая вкладка вытесняет старую) | Решили поддержать несколько вкладок и устройств |
| Heartbeat раз в 15 с | Обрыв замечался за 60–90 с: первая запись в закрытый сокет проходит, а звеньев два |
| События без seq с полным значением и маркер подписчика (`SUBSCRIBED` в той же транзакции, события до маркера отбрасываются) | Данные читались при раздаче, порядок не проверялся на клиенте; заменено seq и патчами |
| Одно событие `users-changed` с полным списком участников | Патчи по участнику мельче и применяются общим применителем; сложности на клиенте нет |
| Опрос комнаты раз в 2 с | Задержка и лишние запросы |

## Последствия

- Обрыв клиента замечается за 10–30 с, всё это время пользователь считается присутствующим.
- Подписка на поток — GET, меняющий данные (вход). Открыть его переходом по ссылке или с другого хоста не даёт проверка Fetch Metadata ([session-tokens](../security/session-tokens.md)).
