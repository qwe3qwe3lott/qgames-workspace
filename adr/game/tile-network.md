# Модель игры на выкладывании тайлов

Область: backend, frontend · Диаграммы: [c4/3-backend-games](../c4/3-backend-games.md) · Код: `backend/games/croissant-game`, `frontend/packages/games/croissant`

## Контекст

«Круассан» — сеть пекарен: игроки выкладывают тайлы кварталов, тянут мучные тропы, растят пекарни с вывесками, открывают
сыроварни и пасут стада на лугах. Состояние партии — свёртка журнала событий, фронт правил не знает и рисует только
`moveOptions`, а платформа не хранит ничего, кроме журнала. Нужно было решить, где живёт колода, где геометрия тайлов и
как считать связные участки.

## Решение

- **Одна стадия `play`, ход из двух шагов**: `PLACE_TILE` (обязателен) и затем `PLACE_CONFECTIONER` или
  `SKIP_CONFECTIONER`. Часы игрока покрывают весь ход; шаг кондитера — не стадия, иначе каждый ход давал бы лишние события
  на переход.
- **Каталог тайлов приходит с карточкой игры** (`GET /api/games/{gameCode}` → `assets.tiles`, 14 типов; источник —
  `GameRules.assets`), а состояние ссылается на тип тайла по `code` (`board[].tile`, `currentTile`). Клиент рисует по
  данным сервера и не дублирует геометрию. Маршрут комнаты и так ждёт карточку игры в loader, поэтому каталог есть до
  доски без лишнего запроса. Порядок колоды — из seed партии (`room_session.seed`) и в состояние не попадает: в
  состоянии только счётчик `deckPos`/`deckSize` и моменты возврата тайла в колоду (`deckReturns` — `deckPos` на тот
  момент; место вставки сервер выводит из seed).
- **Модель тайла и его рисунок** — [tile-model](tile-model.md).
- **Связные участки (`spots`) пересобираются из поля целиком** после каждого тайла: пекарни, тропы и луга объединяются
  по рёбрам и полуребрам, кондитеры переезжают на объединённый участок. Идентификатор участка сохраняется: у
  объединённого остаётся наименьший из прежних, у нового он выводится из тайла.
- **Крошки** сразу за завершённое: пекарня 2 за тайл + 2 за вывеску, тропа 1 за тайл, сыроварня 9; большинство
  кондитеров, при равенстве — всем лидерам. Завершённое тайлом считается в конце хода, после шага кондитера
  (`pending.completed`): на свободный участок, который игрок только что завершил, можно поставить кондитера — он сразу
  приносит крошки и возвращается в запас. Итоговый подсчёт, когда колода кончилась: пекарня 1 + 1 за вывеску, тропа 1,
  сыроварня 1 + соседи, луг 3 за каждую завершённую пекарню рядом.
- **`moveOptions`** отдают не плоский список действий, а сжатые варианты: клетки у края поля с допустимыми поворотами
  (`placements: [{x, y, rotations}]`) и участки нового тайла для кондитера (`spots: [id]`).
- **Время вышло — игрок выбывает** (`players[].out`): больше не ходит и не может победить, но крошки ему считаются,
  его кондитеры остаются на поле. Невыложенный тайл возвращается в колоду, шаг кондитера закрывается, очередь пропускает
  выбывших. Остался один невыбывший — итоговый подсчёт и победа (`reason` `TIMEOUT`).

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Стадии `place-tile` и `place-confectioner` | Два перехода стадии на каждый ход: лишние `stage-changed`, `timer-started`, `move-options-changed` в журнале |
| Колода в состоянии и маскирование закрытых тайлов | Порядок тайлов утёк бы в проекцию игрока; маска на каждое событие выкладки |
| Каталог тайлов в коде фронта | Геометрия дублируется и расходится с сервером; DLC потребовали бы правок фронта |
| Каталог тайлов в состоянии (`state.tiles`) | ~10 КБ в каждом снапшоте: платит каждое подключение зрителя и кеш состояний |
| Отдельная ручка `GET /api/games/{gameCode}/assets` или `/api/games/croissant/tiles` | Лишний запрос и ещё одна ручка; ручка одной игры в общем модуле расходится с «код игры в пути + полиморфные DTO» |
| Отдельные таблицы и миграции под партию «Круассана» | Настройки и состояние живут в общих таблицах платформы |
| Инкрементальное слияние участков с событиями слияния | Книга слияний и миграция кондитеров руками; пересборка из поля проще и проверяема |
| Подсчёт завершённого сразу при выкладке тайла | Игрок не может занять участок, который сам завершил, и теряет крошки за свой же ход |
| Таймаут сам кладёт случайный тайл | При кончившемся запасе партия доигрывается сама: каждый ход сразу уходит в таймаут |
| Невыложенный тайл выбывшего — в сброс | Колода теряет тайл: состав партии зависит от таймаутов |
| Время вышло — партия заканчивается для всех | Один медлительный игрок обрывает партию остальным |
| Очки копить только в конце | Пекарни и тропы в правилах приносят крошки сразу, иначе игрок не видит выгоды хода |

## Последствия

- Пересборка участков и `placements` — O(поле) на ход; поле к концу партии ≤ 72 тайла, это дёшево.
- Снапшот лёгкий: каталог грузится один раз с карточкой игры, фронт не знает ни одного тайла в коде. Карточку игры
  со списком комнат тоже сопровождает каталог (несколько КБ после gzip) — принято.
- Новая DLC — новые типы тайлов в каталоге и новые поля фич; форма контракта не меняется.
- Состав колоды (72 тайла, 14 типов) — рабочая заготовка: баланс проверяется плейтестом, а не тестами.

## Открытые вопросы

- Решить при первой DLC: включение модулей в настройках комнаты и фильтрация каталога по модулям.
- Решить при работе над тач-устройствами: панорама и зум доски жестами (сейчас кнопки масштаба и прокрутка).
